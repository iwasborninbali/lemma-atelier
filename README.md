# lemma-atelier — пошив лемм по правилам ателье

Конвейер, в котором лемма рождается из **нужды в счёте**, проходит через **гейты, которые запускает не автор**, и выходит
в форме, которую **возьмёт другой**. Наследует форму `~/projects/atelier` (цеха, гейты, нить, «переход = файл») и
дисциплину `~/projects/moves` (ставка числом до счёта, противник до приёмки, отрицательный результат законен).
Полигон — задача no-three-in-line и её родня (`~/saturation`); первые нужды — из ночи 2→3.09.2026.

## Две оси и третье поле (решение владельца, 3.09)

- **Доказано** (ось хребта): `не доказано` → `доказано` → `проверено машиной на малых случаях` → `формализовано (Lean)`.
  «Очевидно» — не статус: очевидная дыра закрывается доказательством, не ссылкой на очевидность.
- **Дальность** (П / Б / О по шкале владельца): пессимистично — стоит и не опровергается; базово — лаборатория с
  ресурсами может довести до следующего балла; оптимистично — то же с лучшим исходом.
- **Кто возьмёт**: форма, в которой лемму заберёт другой — чистая общая формулировка + контрпример на границе.

## Нить

`need-NNN` (нужда: вычисление, которому нужно общее утверждение, с файлом-свидетельством) → `conj-NNN` (гипотеза с числом,
ставка в `~/projects/moves/ledger.jsonl` до счёта) → фальсификация перебором → опознание («известно ли?») → `lem-NNN`
(доказательство + машинная проверка) → противник → обобщение → носители → выпуск. Каждое звено ссылается на предыдущее по id;
`gates/lint.py` рвёт шлагбаум на обрыве в обе стороны. Журнал ставок — один, в `moves` (одна дверь).
